API Atlas

MVP de la plataforma Atlas de CreaLab SpA (Caso A): gestión de clientes y de sus contratos con estado calculado, login con JWT y roles ADMIN / EDITOR. Construido con Spring Boot, arquitectura limpia y SQLite.

Spring Boot 3 Java 21 Spring Security + JWT bcrypt SQLite OpenAPI Arquitectura limpia

Endpoints

Método Ruta Descripción Rol
POST /api/v1/auth/login Inicia sesión y entrega un JWT (15 min) Público
POST /api/v1/auth/logout Cierra la sesión revocando el token Autenticado
GET /api/v1/clientes?nombre=&pagina=0&tamano=10 Lista clientes con filtro y paginación ADMIN, EDITOR
GET /api/v1/clientes/{id} Obtiene un cliente ADMIN, EDITOR
POST /api/v1/clientes Crea un cliente ADMIN
PUT /api/v1/clientes/{id} Actualiza un cliente ADMIN
DELETE /api/v1/clientes/{id}?confirmar=true Eliminación lógica con confirmación ADMIN
GET /api/v1/clientes/{id}/contratos Contratos del cliente con su estado ADMIN, EDITOR
POST /api/v1/clientes/{id}/contratos Crea un contrato para el cliente ADMIN
GET /api/v1/contratos/{id} Obtiene un contrato con su estado ADMIN, EDITOR
PUT /api/v1/contratos/{id} Actualiza un contrato ADMIN
DELETE /api/v1/contratos/{id} Elimina un contrato ADMIN

Arquitectura limpia

Dominio

  • Modelos Cliente, Contrato, Usuario
  • Reglas: EstadoContrato, Rut
  • Puertos *Gateway y excepciones

Aplicación

  • ClienteUseCase, ContratoUseCase
  • AuthUseCase (login, bloqueo, logout)
  • Log de auditoría

Infraestructura

  • Adaptadores REST y JPA / SQLite
  • Spring Security + JWT + bcrypt
  • Cabeceras de seguridad y OpenAPI

Cómo probarlo

1. Iniciar sesión (usuarios de demostración admin y editor):

curl -X POST http://localhost:8080/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"nombreUsuario":"admin","contrasena":"Admin#Atlas2026"}'

2. Usar el accessToken recibido:

curl http://localhost:8080/api/v1/clientes \
  -H "Authorization: Bearer <accessToken>"
